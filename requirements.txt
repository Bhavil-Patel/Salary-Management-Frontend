4. FUNCTIONAL REQUIREMENTS (FR)
--------------------------------------------------------------------------------

FR-1: Master Data Management
- Maintain relational tables for Employees, Departments, Job Titles, and Countries.
- Support multi-currency codes (INR, USD, CAD, EUR, GBP, etc.) tied to Country records.
- Track base monthly/annual CTC per employee.

FR-2: Automated Salary Breakdown Engine
- Automatically decompose base CTC into standardized statutory components:
  * Basic Salary          = 50% of Base CTC
  * House Rent Allowance  = 20% of Base CTC
  * Conveyance Allowance  = 5% of Base CTC
  * Medical Allowance     = 5% of Base CTC
  * Special Allowance     = Remaining balance (~20%) of Base CTC
  * Bonus                 = Custom input amount or percentage
  * Gross Salary          = Sum of all earnings components + Bonus

FR-3: Statutory Deductions & Tax Slabs
- Calculate statutory withholdings according to standard labor regulations:
  * Provident Fund (PF)   = 12% of Basic Salary
  * Professional Tax (PT) = Flat 200 if Base Salary > 15,000; 0 otherwise
  * TDS / Income Tax      = Projected Annual CTC Slabs:
                            - Annual CTC > 1,000,000 => 10% of monthly Gross
                            - Annual CTC between 500,001 and 1,000,000 => 5% of monthly Gross
                            - Annual CTC <= 500,000 => 0% TDS
  * Other Deductions      = Custom unpaid leave, loan advances, loss of pay
  * Total Deductions      = PF + PT + TDS + Other Deductions
  * Net Salary Payable    = Gross Salary - Total Deductions (minimum 0)

FR-4: Monthly Payroll Generation & Batch Processing
- Provide one-click monthly payroll generation for selected Month and Year.
- Support department-level batch generation or company-wide generation.
- Prevent duplicate payroll creation for the same employee in the same period.
- Support manual adjustment of bonus, unpaid leave deductions, and remarks prior to disbursement.

FR-5: Single & Bulk Salary Disbursement
- Single mark-as-paid functionality recording payment date and method:
  * BANK_TRANSFER, UPI, CHEQUE, CASH.
- Bulk disbursement marking all pending payroll records for a month as PAID in one transaction.
- Read-only locking of paid records to preserve financial auditability.

FR-6: Official Payslip & Direct PDF Download
- Provide a clean, formatted Payslip Modal displaying company header, employee metadata,
  itemized earnings vs deductions, net payable callout in words, and signature boxes.
- Direct client-side PDF download using html2pdf.js without triggering browser print dialogs.
- Automatic PDF naming: Salary_Slip_<Employee_Name>_<Month>_<Year>.pdf.
- 2x canvas scaling with zero letter clipping or vertical text truncation.

FR-7: Salary Revisions & Appraisal Audits
- Interactive two-way calculator: typing New CTC computes increment %, typing increment %
  computes New CTC.
- Automatically update employee's master salary in the database upon approving a revision.
- Preserve full audit logs: employee, previous salary, new salary, increment %, effective date,
  revision type (Annual Appraisal, Promotion, Market Correction, etc.), and remarks.

FR-8: Multi-Criteria Search, Filtering & One-Click Reset
- Real-time search by employee name or email address debounced at 400ms.
- Filters by Month, Year, Department, and Payment Status (PROCESSED, PAID, DRAFT).
- Prominent "Clear Filters" button in filter toolbars to reset all parameters to default in one click.
- Inline "x" clear buttons inside search input fields for instant input clearing.
- Contextual empty states offering a "Reset all filters" button when 0 records match.

--------------------------------------------------------------------------------
5. NON-FUNCTIONAL REQUIREMENTS (NFR)
--------------------------------------------------------------------------------

NFR-1: Performance & Query Optimization
- Paginated table queries must resolve in < 300ms.
- Sequelize ORM queries joining Employee associations must use subQuery: false and
  required: true when search filters are active to prevent nested pagination bottlenecks.
- Client search queries must use a 400ms debounce to prevent redundant backend load.

NFR-2: Viewport & Layout Integrity
- Body viewport must lock (overflow: hidden via useBodyScrollLock) whenever dialogs or
  payslip modals are open to prevent background page displacement.
- Fully responsive design supporting mobile (320px+), tablet, and desktop viewports.

NFR-3: Data Integrity & Transactions
- Soft deletion (paranoid: true) must be enabled on critical payroll and revision tables.
- Foreign key constraints must enforce relational integrity between employees, departments,
  jobs, countries, payrolls, and revisions.

NFR-4: Document Export Fidelity
- Generated PDF documents must conform to standard A4 proportions.
- Canvas capture must use scrollX: 0 and scrollY: 0 to prevent coordinate shifts.

6. DATABASE SCHEMA SPECIFICATION
--------------------------------------------------------------------------------

Table: employees
- id: INT (PK, Auto Increment)
- full_name: VARCHAR(255), NOT NULL
- email: VARCHAR(255), NOT NULL, UNIQUE
- job_id: INT, FK -> jobs.id
- department_id: INT, FK -> departments.id
- country_id: INT, FK -> countries.id
- salary: DECIMAL(12,2), NOT NULL
- hire_date: DATE, NULL
- created_at: DATETIME
- updated_at: DATETIME
- deleted_at: DATETIME (Soft Delete)

Table: payrolls
- id: INT (PK, Auto Increment)
- employee_id: INT, FK -> employees.id
- month: INT, NOT NULL (1 to 12)
- year: INT, NOT NULL
- basic_salary: DECIMAL(12,2), NOT NULL
- hra: DECIMAL(12,2), NOT NULL
- conveyance_allowance: DECIMAL(12,2), NOT NULL
- medical_allowance: DECIMAL(12,2), NOT NULL
- special_allowance: DECIMAL(12,2), NOT NULL
- bonus: DECIMAL(12,2), DEFAULT 0.00
- gross_salary: DECIMAL(12,2), NOT NULL
- pf_deduction: DECIMAL(12,2), NOT NULL
- professional_tax: DECIMAL(12,2), NOT NULL
- tds_tax: DECIMAL(12,2), NOT NULL
- other_deductions: DECIMAL(12,2), DEFAULT 0.00
- total_deductions: DECIMAL(12,2), NOT NULL
- net_salary: DECIMAL(12,2), NOT NULL
- payment_method: ENUM('BANK_TRANSFER','UPI','CHEQUE','CASH')
- payment_date: DATE, NULL
- status: ENUM('PROCESSED','PAID','DRAFT'), DEFAULT 'PROCESSED'
- remarks: TEXT, NULL

Table: salary_revisions
- id: INT (PK, Auto Increment)
- employee_id: INT, FK -> employees.id
- previous_salary: DECIMAL(12,2), NOT NULL
- new_salary: DECIMAL(12,2), NOT NULL
- increment_percentage: DECIMAL(5,2), NOT NULL
- effective_date: DATE, NOT NULL
- revision_type: VARCHAR(100), NOT NULL
- remarks: TEXT, NULL

7. REST API SPECIFICATION
--------------------------------------------------------------------------------

Payroll APIs:
- GET    /api/payroll                 Fetch paginated payroll list & summary metrics
- GET    /api/payroll/:id             Fetch single payroll details
- POST   /api/payroll/generate        Generate monthly payroll in bulk
- POST   /api/payroll/create          Create manual payroll entry
- PUT    /api/payroll/:id             Update bonus, other deductions, remarks
- POST   /api/payroll/:id/pay         Mark individual payroll as PAID
- POST   /api/payroll/bulk-pay        Mark entire month as PAID
- DELETE /api/payroll/:id             Soft-delete payroll record

Salary Revision APIs:
- GET    /api/salary-revisions        Fetch revision history logs
- POST   /api/salary-revisions        Create revision & update employee CTC
- DELETE /api/salary-revisions/:id    Delete revision record

Master Data APIs:
- GET    /api/employees               List employees (paginated + search)
- GET    /api/departments             List all departments
- GET    /api/jobs                    List all job designations
- GET    /api/countries               List countries and currency codes
